0.4.0 makes a prompt nobody answers stop the agent instead of hanging it, gives every stage the same prompt choices, and lets a decision model see what you asked for. It is also the first release published from a git tag.

**Prompts time out.** A confirm prompt nobody answers is now a block after 60 seconds (`promptTimeoutMs`), with the countdown in the dialog. The agent gets back a reason that says there was no answer, so it stops and asks you rather than working around it. `promptTimeoutMs: 0` waits for you however long it takes. I leave the default on: an unattended session should stop rather than guess.

**Every stage asks the same way.** A classifier score or a chat model verdict now offers the pattern choices your own `ask` rules offered: allow for this session, and where the command allows it, always allow. A command that runs a file gets that file as the pattern, `bash ./wait.sh *`, `python3 tools/gen.py *`, `./target/app *`, so the next call with different flags is covered. Still no pattern for inline code, `sudo`, credential reads, `gh api`, downloaded code, and the programs whose arguments are what they send (`curl`, `wget`, `scp`, `rsync`, `ssh`, `nc`). A path counts as the same program there, so `/usr/bin/curl` gets no pattern either. That was a hole in 0.3.

**A classifier can be told about the session.** Off by default: a decision model sees the command alone, which is what every `askAbove` in the README is tuned against. Two new keys turn it on.

- `classifier.contextChars`: how much of the session the model gets, in characters, counted from your messages and the calls before this one. Tool output and assistant prose stay out. `0` (the default) leaves it off, `1200` is a working starting point.
- `classifier.contextIn`: where that text goes, and this one depends on your server. `state` sends it beside the command as its own key, which Jev and llama.cpp read. `command` folds it into the command text, which is the only way LANCET's server sees it.

The scores move with the extra text, so if you turn it on, re-run the bench and pick a new `askAbove`.

I measured it on a new 100-command set (`bench/suites/mix100.jsonl`) of calls the rules leave open: 48 risky, 52 safe, and 20 where your own message is what decides. `sh bench/context-arms.sh` runs the arms, `node bench/score-arms.mjs` scores them.

| | AUC | wrong asks / misses | on the 20 intent rows |
| --- | --- | --- | --- |
| Jev 1.13, command only | 0.895 | 20 / 5 | 7 / 1 |
| Jev 1.13, with the session | 0.901 | 17 / 4 | 4 / 1 |
| Kev-0.8B, command only | 0.853 | 34 / 0 | 13 / 0 |
| Kev-0.8B, with the session | 0.887 | 32 / 0 | 10 / 0 |
| LANCET, command only | 0.699 | 23 / 11 | 9 / 0 |
| LANCET, session folded into the command | 0.635 | 30 / 8 | 15 / 1 |
| Chat model, stage 3 | not scored | 6 / 8 | 0 / 1 |

- Jev gains and pays nothing for it: same 0.2 s per call, and its wrong asks on the intent rows go from 7 to 4. With the session its best cut moves from 0.5 to 0.8, so retune `askAbove` when you turn it on.
- llama.cpp reads the extra state key too, so Kev gains as well. 37 of its 100 scores moved, and a repeat of the command-only run moved none, so that is the session and not inference noise.
- LANCET got worse. Its server reads only the command field, so a state key changed nothing at all, and a paragraph of session around the command pushed its wrong asks from 23 to 30. Leave it at 0.
- The chat model still asks least about calls you asked for: 0 wrong asks on those 20 rows against Jev's 4, at 59 s per call instead of 0.2 s.

Only 20 of the 100 rows carry a message that could change the answer, because most of the intent-shaped bench cases get settled by the rules and never reach a classifier. That caps how much any of this can move, and it is why the default stays at 0.

Also in this release:

- **CI and CD.** `.github/workflows/ci.yml` runs `node test.mjs` on Node 22 and 24. A `v*` tag runs the tests, publishes to npm with [trusted publishing](https://docs.npmjs.com/trusted-publishers/) so no token lives in the repo, and opens the GitHub release you are reading. `npm audit signatures` after an install shows the SLSA provenance on the package.
- **Bench tooling.** `bench/run.mjs` takes `--config`, `--arm`, `--context-chars`, `--context-in` and `--shard`. `bench/make-mix100.mjs` builds the mixed set from the other suites, weighted to the categories a classifier gets wrong, and `bench/score-arms.mjs` prints AUC, false blocks and misses at a fixed and at the best threshold, and per-category score shifts against a baseline arm.
- **Tests.** New checks for the prompt timeout and a dismissed prompt, the pattern rules above, and exactly what a classifier is told about a call.
